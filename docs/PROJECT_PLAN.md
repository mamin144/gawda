# خطة مشروع نظام متابعة الجودة المالية للمواقع (النسخة التنفيذية المحدّثة)

> **هذا الملف هو المرجع الوحيد للمشروع.** أي قاعدة مالية أو منطق أعمال غير مذكور هنا بوضوح **لا يُفترض**، وإنما يُسجَّل كسؤال في `docs/OPEN_QUESTIONS.md` ويتوقف العمل عنده حتى يُجيب المالك.
> آخر تحديث: 22 نوفمبر 2026.

## 1. القرارات المعتمدة

| البند | القرار |
|---|---|
| الفكرة | تطبيق إدارة ومتابعة الجودة المالية للمواقع فقط. **تم إلغاء فكرة الـ Automation** (تذكيرات، OCR، WhatsApp) |
| الحجم | 30 إلى 50 موقعًا. لكل موقع **شهادة واحدة** لكل فترة (نصف شهر) = نحو 100 شهادة شهريًا |
| الشهادة | سكان ورقة واحدة، أقل من 1 ميجا (PDF أو صورة) |
| الوصول | من أي مكان عبر الإنترنت، والاستضافة السحابية مقبولة |
| قاعدة البيانات والملفات | **Supabase** (PostgreSQL + Auth + Storage + RLS). مشروع تطوير مجاني الآن، ثم خطة Pro (نحو 25 دولارًا شهريًا، تُراجع الأسعار وقت القرار) عند التشغيل الفعلي |
| الواجهة | **Flutter** بكود واحد: Android + Web أولًا (iOS مؤجل لحين التأكيد) |
| نطاق Excel الحالي | الأوراق الأربع فقط: `2025`، `الجودة 2024`، `الجواب`، `الجودة اجمالي`. باقي الأوراق خارج النطاق |
| الأدوار | دوران فقط: **Admin** و**مسؤول موقع** |
| المراجعة والاعتماد | يقوم بهما **Admin فقط**. لا أدوار مراجع/معتمد منفصلة |
| النسخة المعتمدة | **النسخة الموقّعة هي النسخة المعتمدة**. رفعها يقفل الشهادة ولا توجد خطوة اعتماد إضافية |
| حذف النسخة الأولى | تُحذف نهائيًا من التخزين بعد التأكد من حفظ النسخة الموقّعة بنجاح، مع بقاء **سجل وصفي** (من رفعها، التاريخ، الحجم، Hash) وسطر في سجل التدقيق |

## 2. قاعدة الفترات (معتمدة)

- **الفترة الأولى:** من 1 إلى 15 (يوم 15 ضمنها).
- **الفترة الثانية:** من 16 إلى آخر الشهر (28 أو 29 أو 30 أو 31).
- الفترة تُحدَّد من **تاريخ الشهادة نفسها**، وليس تاريخ رفعها. شهادة بتاريخ 10 تُسلَّم يوم 20 تُحسب للفترة الأولى.
- تاريخ الرفع يُسجَّل تلقائيًا كحقل منفصل.
- لكل موقع **شهادة واحدة فقط** في كل فترة (قيد فريد في قاعدة البيانات).
- لا يوجد جدول فترات منفصل: الفترة تُشتق من تاريخ الشهادة بدالة قاعدة بيانات.

## 3. الأدوار والصلاحيات

| الصلاحية | Admin | مسؤول موقع |
|---|---|---|
| لوحة شاملة ومقارنة المواقع | ✅ | ❌ |
| إدارة المواقع والمستخدمين | ✅ | ❌ |
| إدخال شهادة ورفع مرفقات | ✅ | ✅ مواقعه فقط |
| تعديل شهادة | ✅ بعد القفل مع تسجيل السبب (إعادة فتح) | ✅ فقط وهي مسودة أو مرتجعة |
| مراجعة وإرجاع بملاحظة وموافقة مبدئية | ✅ | ❌ |
| رفع النسخة الموقّعة (يقفل الشهادة) | ❌ | ✅ |
| استيراد Excel | ✅ | ❌ |
| تقارير وتصدير | كل المواقع | موقعه فقط |
| سجل التدقيق | ✅ | ❌ |

**مبادئ ملزمة**
- عزل المواقع يُفرض في **قاعدة البيانات (RLS)** وليس الواجهة.
- الـ Admin **لا يعدّل القيم المدخلة**، وإنما يوافق أو يرجّع بملاحظة.
- لا حذف نهائي للسجلات المالية: Soft Delete فقط (الاستثناء الوحيد: ملف النسخة الأولى كما في البند 1).
- الدور يُخزَّن في جدول `profiles` محمي بـ RLS، **وليس في `user_metadata`** لأن المستخدم يستطيع تعديله.

## 4. دورة حياة الشهادة (Workflow)

```
مسؤول الموقع: إدخال البيانات + رفع السكان الأول ← إرسال
Admin يراجع:
   ├─ إرجاع بملاحظة ← مسؤول الموقع يعدّل ويرسل من جديد
   └─ موافقة مبدئية ← "في انتظار التوقيع"
مسؤول الموقع: يوقّع الشهادة ويرفع السكان الموقّع
النظام: التحقق من حفظ الملف ← قفل الشهادة ← حذف ملف النسخة الأولى (مع الاحتفاظ بالسجل الوصفي)
```

| الحالة (`status`) | من يتحرك | التعديل |
|---|---|---|
| `draft` مسودة | مسؤول الموقع | مسؤول الموقع |
| `in_review` قيد المراجعة | Admin | لا أحد |
| `returned` مرتجعة | مسؤول الموقع | مسؤول الموقع |
| `awaiting_signature` في انتظار التوقيع | مسؤول الموقع | رفع الملف الموقّع فقط |
| `approved` معتمدة ومقفلة | | Admin فقط مع سبب (إعادة فتح تنقلها إلى `returned`) |

**كل انتقال بين الحالات يُنفَّذ عبر دوال RPC في قاعدة البيانات (Security Definer) ويُسجَّل في سجل التدقيق. لا يُسمح بتعديل `status` مباشرة من العميل.**

## 5. المرفقات

- حاوية Storage **خاصة (Private)**، الوصول عبر روابط مؤقتة موقّعة فقط.
- المسار: `site_id/سنة/شهر/نصف/اسم_فريد`.
- الأنواع: PDF وJPG وPNG. الحد الأقصى المبدئي 2 ميجا، وضغط الصور قبل الرفع.
- بصمة الملف (SHA-256) لمنع رفع نفس الملف مرتين.
- نوعان للمرفق: `initial` (الأول) و`signed` (الموقّع).
- حذف الملف الأول يتم بعد التحقق من حفظ الموقّع، عبر **Edge Function** تعمل بصلاحية الخدمة من جهة الخادم فقط (مفتاح `service_role` لا يوجد أبدًا داخل تطبيق Flutter).
- إعادة الفتح لا تحذف النسخ الموقّعة السابقة: تُحفَظ كنسخ سابقة.

| الطبقة | الاختيار |

| إدارة الحالة | `flutter_bloc` (Bloc/Cubit) |

| المظهر | Material 3، عربي RTL أولًا، رموز تصميم (Theme Extensions)، خطوط عربية مضمّنة في الأصول |

## 7. قاعدة البيانات (الكيانات المقترحة)

| الكيان | ملاحظات |
|---|---|
| `profiles` | يرتبط بـ `auth.users`، فيه `role` (`admin` / `site_user`) و`is_active` |
| `sites` | كود، اسم، حالة، أرشفة |
| `user_sites` | ربط المستخدم بالمواقع |
| `certificates` | `site_id`، `certificate_date`، أعمدة الفترة المشتقة (سنة/شهر/نصف)، `amount numeric(18,2)`، `notes`، `status`، `return_note`، `created_by`، `submitted_at`، `locked_at`. **قيد فريد: (site_id، سنة، شهر، نصف)** |
| `attachments` | `certificate_id`، `kind`، `storage_path`، `file_name`، `mime`، `size_bytes`، `sha256`، `uploaded_by`، `uploaded_at`، `deleted_at`، `deleted_by`، `delete_reason` |
| `audit_logs` | إضافة فقط (Append-only): من، ماذا، متى، قبل، بعد، السبب |

**ملاحظات تصميم**
- `amount` هو الحقل الوحيد المؤكد للقيمة المالية حاليًا (قيمة واحدة لكل موقع لكل نصف شهر كما في Excel). أي حقول إضافية في الشهادة **لا تُضاف** قبل رؤية عينة شهادة حقيقية.
- دقة `numeric(18,2)` مبدئية وقابلة للتغيير بترحيل (Migration) بعد قرار الدقة.
- كيانات `Payments` و`Budgets` و`Adjustments` و`ImportBatches` و`CalculationRules` **مؤجلة** حتى تُحسم الأسئلة المفتوحة.

## 8. الأمان

- RLS مفعّل على **كل** الجداول. سياسات مبنية على `auth.uid()` و`profiles` و`user_sites`.
- دوال Security Definer مع `search_path` ثابت، وبدون عرض بيانات حساسة عبر Views عامة.
- سياسات Storage مرتبطة بنفس منطق عزل المواقع.
- إنشاء المستخدمين يتم عبر **Edge Function** (لأن إنشاء مستخدم Auth يحتاج صلاحية الخدمة)، وتتحقق أن المستدعي Admin.
- لا أسرار في الكود أو Git. ملف `.env` خارج التتبع، وعميل Flutter يستخدم فقط عنوان المشروع ومفتاح `anon`.
- فحوصات إلزامية: RLS tests، مستشارو Supabase (Security/Performance Advisors)، فحص إعدادات افتراضية غير آمنة، فحص الأسرار قبل كل إصدار.
- المصادقة الثنائية للـ Admin: مؤجلة.

## 9. نتائج تحليل Excel (الأوراق الأربع)

### الدفتر الرئيسي (ورقة `2025`)
- 40 صف مشروع (الصفوف 5-44) وصف 45 للإجمالي، و31 صفًا مخفيًا.
- أعمدة ثابتة: إجمالي الأعمال حتى يناير 2025 (C)، المسدد لتسوية 14/4/2023 (D)، المسدد 30/1/2025 (E)، والصافي `F = C − D − E`.
- لكل شهر 3 أعمدة: النصف الأول، النصف الثاني، والإجمالي (= مجموعهما). البيانات من فبراير 2024 إلى أكتوبر 2025 (1-15).
- **لا يوجد في الملف رقم شهادة ولا تاريخ شهادة**: قيمة واحدة لكل موقع لكل نصف شهر.

### المعادلات كما وردت في الملف (غير معتمدة كقواعد نهائية)

| العمود | العنوان | المعادلة |
|---|---|---|
| BX | إجمالي الاختبارات بالموازنة الجديدة | مجموع إجماليات الشهور + F |
| BY / BZ / CA | المسدد (شؤون مالية / تحت المراجعة / إيداعات التموين) | إدخال يدوي |
| CB / CC / CD | تصحيحات / إيصالات مرفوضة / فائض عام | إدخال يدوي |
| CE | المطلوب من المواقع | `BX − (BY+BZ+CA+CB+CC+CD)` |
| CF | إجمالي الاختبارات | `C − F + BX` |
| CG | إجمالي المحصل | `CA + BZ + BY + E + D` |
| CH | المحصل طبقًا لجوابات الموقع | يدوي (معظمه 0) |
| CI | الفرق | `CG − CH` |

### الميزانيات الثلاث (ورقة `الجودة اجمالي`)
الأولى 2021/1/1 إلى 2023/4/15 (20.24 مليون)، والثالثة 2023/4/16 إلى 2025/4/15 (تشمل 8.567 مليون مرحّلة)، والثانية من 2025/2/1 بلا نهاية (تشمل 18.3 مليون مرحّلة). التسمية والتواريخ متداخلة وتحتاج تأكيد الإدارة.

### مشاكل وجدت في الملف
1. إجمالي BX في صف 45 **ناقص 5,634,024** لأن إجماليات يونيو إلى أكتوبر 2025 (BE, BH, BK, BN, BQ) غير مجمّعة، وملخص `الجودة اجمالي` يعرض متبقيًا 926,959 بدل 6,560,983 (= CF − CG).
2. نطاقات الجمع غير موحدة (حتى صف 41 أو 42 أو 44).
3. معادلة BX بنوعين (28 صفًا تقف عند BK و12 صفًا تضيف BN-BW).
4. CE أرقام يدوية في 6 صفوف، وCG بثلاث صيغ، وCH فيه معادلة بأرقام ثابتة، وCD1 وCF2 فيهما أرقام مكتوبة داخل المعادلة.
5. ترقيم: 39 مكرر، و"شمال ميدواي" بلا رقم، ولا يوجد 38.
6. عناوين الفترات بصيغ مختلفة وأخطاء إملائية.
7. ملاحظات مالية مهمة مخزنة كـ Cell Comments (إيصال مرفوض، جواب مرتد...).
8. رابطان خارجيان (ملف Word على D:\ وملف 15-10.xlsx)، وقيمة في `الجودة اجمالي` تعتمد على أحدهما.
9. نفس الفترات التاريخية في طبقتين (`الجودة 2024` و`2025`) بتخطيطين مختلفين.

## 10. استيراد Excel (محجوز لحين حسم الأسئلة)

لا يُنفَّذ قبل حسم الأسئلة 1 إلى 4 في البند 13. عند التنفيذ:
- الاستيراد حسب **موضع العمود** وليس نص العنوان، مع قراءة الصفوف المخفية.
- جدول مطابقة (Mapping) تعتمده الإدارة، وكل معادلة تُوثَّق كقاعدة بنسخة (Versioning).
- Preview ثم اكتشاف التكرار والأخطاء ثم مراجعة ثم اعتماد، على دفعات مع إمكانية التراجع.
- **Reconciliation** بعد الاستيراد: إعادة حساب الإجماليات لكل موقع وشهر ومقارنتها بالملف، ولا يُعتمد الاستيراد قبل حل أي فرق.
- لا ننقل أخطاء Excel. الإجماليات تُحسب من البيانات الخام.
- ملف Excel الأصلي وكلمة مروره **لا يوضعان في المستودع**.

## 11. تصور UX/UI

- عربي أولًا (RTL كامل)، بسيط جدًا لمسؤول الموقع، ولوحات واضحة للـ Admin.
- **مسؤول الموقع:** تنقل سفلي (الرئيسية / إدخال / السجلات / حسابي)، بطاقة كبيرة "الفترة الحالية: مطلوب / مُرسل"، زر إضافة واضح، حفظ تلقائي للمسودة، كاميرا الموبايل لمسح الورقة ورفعها.
- **Admin:** قائمة جانبية على الويب. لوحة أرقام علوية، مقارنة المواقع، قائمة "تحتاج انتباه" (متأخر، قيد المراجعة، مرتجع)، فلتر ثابت للموقع والفترة، شاشة مراجعة مع معاينة المرفق وأزرار (موافقة مبدئية / إرجاع بملاحظة).
- ألوان الحالات: أخضر معتمد، أصفر يحتاج مراجعة، أحمر متأخر أو مرتجع، رمادي مؤرشف.
- إمكانية وصول (تباين ≥ 4.5:1، أهداف لمس ≥ 48dp، دعم تكبير الخط).
- المجاميع في اللوحات = **مجاميع خام للقيم المدخلة فقط** إلى أن تُعتمد قواعد الحساب (البند 13).

## 13. الأسئلة المفتوحة (لم تُحسم)

1. **مصدر الحقيقة:** هل `الجودة 2024` و`2025` متداخلتان؟ ومن أي فترة نعتمد كل منهما؟
2. **الميزانيات:** القاعدة الصحيحة للتواريخ والترحيل (8.567 و18.3 مليون)؟
3. **المعنى المالي:** "المطلوب من المواقع" (CE) و"المحصل طبقًا لجوابات الموقع" (CH)، ولماذا CH غالبًا صفر؟
4. **الإجمالي:** هل إجمالي BX المقصود مجموع **كل** الشهور؟ (الرقم الحالي ناقص 5,634,024)
5. **حقول الشهادة:** ماذا يُسجَّل غير المبلغ؟ (يحتاج عينة شهادة سكان حقيقية)
6. **الإيصالات (Payments):** هل يسجل النظام المسدد بتفصيله أم الإجمالي فقط؟
7. **المشاريع الشاذة:** معالجة 39 المكرر و"شمال ميدواي" وغياب 38، وأي مشروع بدأ في منتصف فترة.
8. **الدقة:** هل نقرّب لأقرب قرش؟ (بعض القيم فيها كسور حتى ±0.1)
9. **المنصات:** هل iOS مطلوب؟ (الافتراضي الحالي Android + Web)
10. **أرقام الواجهة:** أرقام غربية (0-9) أم عربية؟ (الافتراضي الحالي غربية، قابل للتغيير)

**ما تم إغلاقه:** نطاق الأوراق، المراجع والمعتمد = Admin، النسخة الموقّعة = المعتمدة، الحذف مع سجل وصفي، السحابة مقبولة، قاعدة الفترات.
